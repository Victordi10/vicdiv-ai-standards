# Git Standards

## Commits

Preferir Conventional Commits:

```text
feat:
fix:
refactor:
docs:
test:
chore:
```

Los mensajes deben describir el cambio real.

## Branches

Seguir la convención establecida en el proyecto. No inventar un sistema nuevo si ya existe uno.

## Pull Requests

El cambio debe ser explicable, revisable y acotado.

## Changelog

Actualizar el changelog cuando el proyecto lo utilice y cuando el cambio tenga impacto para usuarios, integraciones o releases.

## Prohibición de cambios destructivos

No eliminar branches, commits, tags ni reescribir historia sin autorización explícita.

No borrar changelog ni documentación como parte de una "limpieza" sin autorización.
